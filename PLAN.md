# TradeCraft — Project Plan

A capital-market trading & portfolio-management Android app (academic MVP, Java).
Users get virtual cash, browse **live** stock prices from a real REST API, and buy/sell
into a Firestore-backed portfolio.

- **Deadline:** 1-week university project — every decision favors speed and simplicity.
- **Workflow:** planning/architecture is done with Claude Code (Opus); phase code is
  generated by a coding agent (Sonnet) one phase at a time, each on its own branch with
  incremental commits. See [CLAUDE.md](CLAUDE.md) for conventions a new session needs.

## 2. Architecture

Three layers, two repositories, no DI framework.

```
View (Activities/Fragments + XML)
  └─ observes LiveData ─┐
ViewModel (one per screen, LiveData state: data/loading/error)
  └─ calls ─┐
Repository
  ├─ UserRepository   → FirebaseAuth + Firestore   (user data, stateful)
  └─ StockRepository  → Retrofit → Finnhub API      (stock data, read-only)
```

- The two repositories never call each other. When a flow needs both (e.g. a trade),
  the **ViewModel orchestrates** them.
- All async flows through one contract: `RepositoryCallback<T>` (`onSuccess(T)` / `onError(String)`).
- Repositories are singletons (`getInstance()`, private constructor).
- ViewModels hold private `MutableLiveData` + expose public `LiveData` getters, toggling a
  `loading` boolean around each call.

## 3. Data Flow & Schema

### Firestore (user data)

```
users/{uid}
├── email:   String
├── balance: double            // seeded 100000.0 on signup (virtual cash)
└── portfolio (subcollection)
     └── {SYMBOL}               // doc id = ticker, e.g. "AAPL"
          ├── symbol:      String
          ├── quantity:    long
          └── avgBuyPrice: double   // weighted average cost basis
```

Design choices: portfolio keyed by ticker → buying more = read-modify-write on one doc;
selling to zero = delete doc. Weighted `avgBuyPrice` avoids storing individual lots.

### Finnhub API (stock data)

Base URL `https://finnhub.io/api/v1/`

- `GET quote?symbol={S}&token={KEY}` → `{ c, h, l, o, pc }` (`c` = current price = trade price)
- `GET stock/profile2?symbol={S}&token={KEY}` → `{ name, ticker, logo }`

JSON → Java mapping (Gson `@SerializedName`): `QuoteResponse`, `CompanyProfile` →
assembled into the app-level `Stock` domain model.

> **MVP shortcut:** Finnhub free tier has weak symbol search, so the Market screen uses a
> hardcoded list of ~10–12 well-known tickers and fetches a live quote for each. "Search"
> = local filter of that list.

## 4. Core Logic — the "Broker" (Phase 4)

The Broker is logic (in a ViewModel/service), not a screen. It orchestrates both repos.

**Buy flow:**
1. Fetch **live** price from the API (never trust a client-passed price).
2. `cost = price * qty`.
3. Read balance from Firestore.
4. Validate `cost <= balance`; else "Insufficient funds".
5. Execute in a **Firestore transaction** (atomic): deduct `balance`, upsert the holding
   (recompute weighted `avgBuyPrice`).

**Sell flow:** mirror image — validate `qty <= owned`, in a transaction add proceeds to
`balance` and decrement quantity (delete the holding doc at zero).

**Security:** trade price is fetched live at execution time (not spoofable from UI);
Firestore Security Rules restrict each user to their own `users/{uid}` document + subtree:

```
match /users/{userId} {
  allow read, write: if request.auth != null && request.auth.uid == userId;
  match /portfolio/{ticker} {
    allow read, write: if request.auth != null && request.auth.uid == userId;
  }
}
```

## 5. UI Flow

4 screens + 1 dialog, dark Material 3 theme.

- **Auth** (`LoginActivity` host) → `SignInFragment` / `SignUpFragment` sharing one
  `AuthViewModel`. Dark mockup style: sparkle brand mark, labeled dark inputs with icons,
  red→purple gradient primary button. Sign Up has a confirm-password field.
- **Main shell** (`MainActivity`) → `MaterialToolbar` + `BottomNavigationView` with
  **Market** and **Portfolio** tabs hosting fragments.
- **Market** (`MarketFragment`) → `RecyclerView` of live stock prices with green/red
  percent change (`profit_green`/`loss_red`).
- **Portfolio** (`PortfolioFragment`) → balance + holdings with live value & unrealized P/L.
- **Trade dialog** → re-fetches live price, qty input, Buy/Sell, validation.
