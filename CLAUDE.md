# CLAUDE.md — TradeCraft

Project context for any new session. Read this first; the full plan is in [PLAN.md](PLAN.md).

## What this is
A capital-market trading & portfolio Android app — **academic MVP, 1-week deadline, Java**.
Virtual cash, **live** stock prices from a real REST API, Firebase-backed portfolios.
Optimize for **speed and simplicity**, not production hardening. Flag academic shortcuts explicitly.

## How we work
- **Planning/architecture** happens in Claude Code (Opus). **Phase code is generated by a
  separate coding agent (Sonnet)** from carefully structured prompts, one phase at a time.
- **One branch per phase**, off `main`; work split into **incremental, conventional commits**
  (`feat:`/`chore:`/`fix:`), each compiling on its own.
- When asked to "write phase N," produce a structured prompt for the coding agent — not a
  code dump — unless explicitly asked to edit files directly.

## Tech stack
- Java, minSdk 24, Java 11. Material 3, **dark theme**, XML view-based layouts.
- **MVVM**: View → ViewModel (LiveData) → Repository. No DI framework, no RxJava, no coroutines.
- Firebase Auth (Email/Password) + Cloud Firestore.
- Retrofit + Gson → **Finnhub** REST API for live quotes. Glide for logos.
- Gradle Kotlin DSL + version catalog (`gradle/libs.versions.toml`). AGP 9 (canary — expect
  occasional preview-toolchain quirks). `compileSdk` uses the new `release(36){}` DSL.

## Code conventions (match these exactly)
- Package root `com.example.tradecraft`; sub-packages `model`, `repository`, `viewmodel`,
  `ui`, `network`.
- **Async:** one contract everywhere — `RepositoryCallback<T>` (`onSuccess(T result)` /
  `onError(String errorMessage)`). Never introduce a second callback type.
- **Repository:** singleton (`getInstance()`, private ctor), wraps its data source; no other
  layer touches Firebase/Retrofit directly. Templates: `UserRepository`, `StockRepository`.
- **ViewModel:** private `MutableLiveData` + public `LiveData` getters; toggle `loading`
  true→false around calls. Templates: `AuthViewModel`, `MarketViewModel`.
- **Model:** plain POJO, no-arg constructor + getters/setters. API models use Gson
  `@SerializedName`. Template: `User`.
- Auth fragments share one `AuthViewModel` scoped to the host activity
  (`new ViewModelProvider(requireActivity())`).

## Design system (already defined — reuse, don't recreate)
- Dark Material 3 theme in `res/values/themes.xml`; brand violet primary, red→purple gradient
  button is the default `materialButtonStyle`.
- Colors in `colors.xml` incl. **`profit_green` (#4ADE80)** and **`loss_red` (#FF6B6B)** —
  use these for P/L / percent-change coloring.
- Tokens: `spacing_*`, `corner_radius_*`, `elevation_card`; text appearances
  (`AppName`, `AuthHeading`, `AuthSubtitle`, `FieldLabel`); styled `CardView`/`TextInputLayout`.
- All user text in `strings.xml`, dims in `dimens.xml`. No hardcoded hex/text in layouts.

    the user should have cash. Root cause is a missing/mistyped `users/{uid}` profile doc:

    field, or non-numeric `balance` as `0.0`, so the `cost > balance` guard always trips.

    or when only `portfolio/{ticker}` docs were seeded without a parent `balance`. Fix: ensure
    the profile doc exists with a numeric `balance` (sign up in-app, not via console), and
    optionally harden `executeBuy`/`executeSell` to throw a clear "account not set up" error
    when `!userSnapshot.exists()` instead of misreporting insufficient funds.

## Build / run notes
- Requires `app/google-services.json` (Firebase) — not committed.
- **Enable Email/Password auth AND create the Cloud Firestore database** in the Firebase
  console. If the Firestore database doesn't exist, profile writes are never acknowledged and
  sign-up hangs — this was the cause of the earlier "sign-up spins forever" symptom.
- Finnhub API key goes in `local.properties` as `FINNHUB_API_KEY=...` (gitignored), surfaced
  via `BuildConfig.FINNHUB_API_KEY` (needs `buildFeatures { buildConfig = true }`).
- After editing `gradle/libs.versions.toml`, run a Gradle sync — unresolved `libs.*`
  references almost always mean the catalog was edited since the last sync.
